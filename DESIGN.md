# de-askew design

## Overview

A desktop archival workbench. The user's photographs take most of the space;
controls stay in a quiet left column. The signature graphic shows a ghosted,
tilted cassette and disc resolving into aligned geometry. It is an illustration,
not a claim that hidden or missing photographic detail can be recovered.

This is a native product interface for archivists, not a marketing page. The
existing name, Commons-photo icon identity, serial batch processor and defaults stay.
The icon now uses a dark teal backplate, two alignment marks and a faint tilted
duplicate over the centered disc. Small-size variants remove the duplicate.
README.md, MACOS.md, WINDOWS.md and the CLI contracts own product behavior.

## Colors

Model B: `discstraight/ui_theme.json` owns the palette. This file mirrors it.
Swift reads it from the bundled engine; Tk reads the same packaged file. The
graphic generator also reads that file. No second platform palette is maintained.
Native controls, focus rings, menus, dialogs and scrollbars keep OS semantics.
The photographic review workbench uses an explicit light appearance on macOS,
matching Windows, so preview backgrounds do not change with system appearance.
Status always has text; color is supplemental. Checks mean transparency in the
preview only. PNG masters retain alpha.

## Typography

Use native system text (macOS system font; Windows Segoe UI), including fallback
for multilingual filenames. Wordmark 28–30 pt, section titles 15–17 pt, controls
12–13 pt, captions 11 pt. Reserve monospace for expandable diagnostic activity.
Filenames may truncate in the middle but expose their full value in tooltips;
dates use local time, with the platform's customary presentation.

## Layout

One main window, approximately 1160 × 800. A 248-point control column sits beside
the independently scrolling before/after history. Minimum window size 900 × 720
keeps controls available. Native file pickers are the keyboard alternative to
dragging files or folders. The fixed footer shows current activity and result
counts. New cards follow the scroll only when the user is already at the bottom.
The diagnostic log is a disclosure, not the dominant screen region.

## Elevation & Depth

Flat surfaces, thin separators and quiet panel fills. Native sheets own modality.
No decorative shadows, gradients, animated backgrounds or hover-only actions.

## Shapes

Slightly rounded review cards, straight dividers and native buttons. The alignment
graphic uses exact circles and rounded rectangles. It is shared between platforms
as `manual/images/alignment.png`, generated by `examples/build_ui_graphic.py`.

## Components

Canonical owners: native AppKit controls in `macos/DiscStraighten.swift` and native
Tk/ttk controls in `discstraight/windows_gui.py`; both invoke the same CLI engine.
OS-owned dropdown geometry and scrollbars are intentional. There is no web form,
table, authentication, remote search or financial transaction in this UI.

Drop/choose queues all filename-sorted input cards → independent thumbnail loading
and conversion → each existing card fills its output → individual comparison or
failure card → persistent completion status. Originals are never overwritten.
Review notices remain visible on their cards. Options start off; media starts
Automatic. Preferences save through the shared validated preference module.
Errors retain the input name and recovery guidance. Busy state disables output
preferences; removing pending batches allows the current batch to finish.

Theme mapping: every palette key maps to `Theme.color` in Swift and `THEME` in Tk;
the alignment generator consumes those same keys. Native focus, disabled and
pressed states remain OS-owned. No motion beyond the native progress indicator.

| Capability | Canonical owner | Source of truth | Allowed variants | Verification |
|---|---|---|---|---|
| File intake | AppDelegate / App | CLI batch input handling | Native AppKit and Tk file pickers and drop targets | Folder batch and failure tests |
| Preferences | OutputPreferences | discstraight/preferences.py | AppKit sheet and modal Tk window | Empty destination, cancel, relative/fixed tests |
| Comparison history | addComparison / card | CLI JSON result events | Native scrolling containers | Multiple results, review/failure cards, scroll retention |
| Theme | ui_theme.json | discstraight/ui_theme.json | Native OS control chrome | Palette drift and rendered app inspection |

| Select/Listbox | NSPopUpButton and ttk.Combobox | Native platform widgets | OS-owned popup | Keyboard open/select/dismiss |
| Scrollbar | NSScrollView and ttk.Scrollbar | Native platform widgets | Separate result history and activity regions | Multiple result scroll and retained position |

## Do's and Don'ts

- Keep many small comparisons visible, with full-resolution files one action away.
- Use an equal shared corner template after perspective rectification.
- Label inferred geometry and keep originals and logs alongside derivatives.
- Never imply checkerboard pixels are present in a transparent master.
- Never move a reader away from an earlier comparison as another file finishes.
- Do not replace native file access, focus behavior or accessibility with art.
